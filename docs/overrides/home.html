FLYPSE / DOCUMENTATION

Emulate federated learning across the Cloud–Edge continuum in Python.

Implement the entities of a federation, split the data across them, and choose the devices they run on. Each device runs in its own process and entities exchange real messages, so the statistics of the data and the limits of the system both shape the learning.

WHAT AN ENTITY DECIDES

A round is six decisions. Change one at a time.

Strategies are plain functions an entity calls inside its own step. Federated averaging, FedAdam or a Byzantine-robust server differ in the one they take for each decision.

  1. SelectionWhom to engage
  2. AssignmentWhat to ask of each
  3. ScreeningWhich updates to use
  4. WeightingHow much each counts
  5. AggregationHow they combine
  6. OptimisationHow the model changes

AFTER A RUN

Read what the entities reported.
Change one assumption.

Entities push the values they need during a run, and each record keeps who reported it, from where and when. Keep the seed explicit when comparing runs.

Read and query results → 
self.report(round=round_, loss=loss)  # in an entity

process.run(seconds=10)
records = process.reported
frame = pandas.DataFrame(records)

A record is a plain dictionary, ready for pandas or any other tool. A process can also collect metrics at every step, as frames.
